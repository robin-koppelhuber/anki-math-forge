the unit

where it is
the section, page and — where the source numbers things — the number it printed. Whatever the source names it by is what makes this unit's id stable: an equation number for a book that has them, a Zotero annotation key for a document you marked up. Neither is a position, which is why adding one more mark renumbers nothing.
the picture
rendered from the PDF on demand, showing a margin of surrounding page with the unit's own box drawn on it — how much is crop_context, and a source may set its own. The box is what this unit claims to be. If the box holds two numbered equations, or the equation continues outside it, segmentation got it wrong — annotate rather than card it. p shows the whole page.
the colours on it
what a reader marked, painted back on in the colours they used. The mark this unit came from is at full strength; everything marked nearby is faded, so a page with six highlights on it still says which one the card is about. A unit that came from a mark is cut to the full width of the page — a mark's box is the union of the lines a sentence happened to span, so its left and right edges are wherever that sentence started and stopped mid-column.
the marks underneath
what each one actually says — the sentence it covers, and anything written beside it. Whether a marked claim is worth a card on its own is mostly a question about its neighbours, and this is them. One marked its own unit you will meet again; the rest are only context for this decision.
the maths beside it
the transcription, rendered. A hint, not content: where it disagrees with the picture, the picture wins. transcribed means something read the crop; not transcribed means run /transcribe, or read the crop yourself.
the grey text underneath
the prose immediately above the equation in the book — the sentence that introduces it. Context for deciding, never a transcription.

what each key does

q queue
This becomes a card. The greenlight: /extract-cards reads everything queued and writes a stub for it. Nothing reaches Anki without you approving the card afterwards, in the review view.
s skip
Never offer this again. Sticky — it survives re-extraction. You are asked for a one-word reason, which is stored.
S skip, with a reason
The same, but asks for one word first. Plain s does not, because a skip is the commonest key in triage and stopping to type turned one keystroke into a dialogue.
u back to new
Undo a decision: the unit returns to the untriaged pool. This is the only way back from a skip.
a accept · d dismiss
Act on a suggestion, or throw it away. Suggestions come from forge classify or from /classify; both only ever propose. Pressing q or s yourself also clears the suggestion — you overruled it.
n annotate
Leave an instruction for Claude, read when the card is written — "two cards, one per layout convention", "the transcription is wrong, read the crop". Also shows up in forge todo.
c context size
How much of the document whoever writes this card is handed: this page only, one page either side, three, ten, or all of it. Cycles through those rather than asking for a number, because the decision is "a bit more" or "all of it" and not a measurement. This is the moment you can tell — the theorem is here and its hypotheses are two pages back, and no per-source default knows that. The badge appears only once a unit asks for something other than the default.
p whole page
Swap the crop for the entire page, with the unit's own box drawn on it. The two ways segmentation fails are only visible against the surroundings: a split equation shows its missing lines outside the box, and two merged into one show two numbers inside it. Press again to go back.
z undo
Undo the last decision, however it was made — a state change, an accepted suggestion, a dismissed one. It restores what was actually there before, including the reason and any suggestion the action cleared, so a mis-pressed key costs one keystroke. Repeat to walk further back.
j / k
Next / previous. Queuing and skipping move you on to the next unit still awaiting a decision — but the one you just acted on stays in the list, so k always gets you back to it.

filters

new / queued / skipped / carded
The unit's state. new is untriaged, carded means a card exists for it.
transcribed
Only units whose tex_auto passed the KaTeX gate, so the maths is written out beside the crop instead of only pictured. The crop stays authoritative — if the two disagree, believe the crop and annotate the unit.
suggested
Only units something has proposed a decision for. A suggestion is never applied on its own — it waits for you. Most units have none, and that is a result rather than a gap: the classifier is not permitted to propose a skip for an equation the book gave a number, because numbering it is the document asserting it is a result. Those are yours to decide, and a/d do nothing on them.

what each key does

a approve
This card is right. Stamps content_hash, and sync will push it to Anki. Editing it afterwards un-approves it — the hash stops matching and it returns here.
u back to draft
Un-approve a card you have changed your mind about. Editing one does this as a side effect — content_hash stops matching — but changing your mind is not an edit, and a token change in the editor would be a worse way to say so. Clears the hash, so nothing syncs it.
r reject
This card is wrong and is not worth fixing. It stays on disk; nothing syncs it.
e open in $EDITOR
Fix it yourself. The app re-reads from disk, and refuses to write over a file that changed underneath it.
z undo
Undo the last approve or reject. Approving stamps content_hash and rejecting drops it, so this restores the hash too — the card goes back to the state it was actually in, not merely to the same status. The card you just acted on also stays in the list, so k reaches it.
n annotate
Leave an @claude note, a request for Claude. Prefix the text @me instead to park a decision for yourself. Sync refuses any card with an open annotation of either kind, whatever its status, so the note alone holds the card back and you do not touch its status. Annotating moves you on to the next card, like every other decision here; k goes back.
r reject — and what it is not
rejected means this card should not exist. It is not a way to park something: an annotated card is already refused by sync whatever its status, so a note alone is enough to hold it back. Rejecting to clear it from the draft list leaves a card Anki is still showing you while the repo says never sync it — sync never deletes. Use no notes in the filter rail to review only what is actually waiting on you.
x resolve
Resolve the card's first annotation, or click resolve on any one of them. Resolving is deleting the line: there is no reply and no done-flag, because a note still in the file still blocks sync. Answering it with a second annotation therefore makes things worse, not better — now two notes block the card. Resolve a @claude note once the work is done; resolve a @me note once you have taken the decision it was holding open. The edit is to ## notes, which is outside content_hash, so resolving does not send an approved card back to draft.
j / k
Next / previous. Approving or rejecting moves you on to the next card still awaiting a decision; the one you just acted on stays in the list, so k reaches it.

what a card is made of

front, then given
The question, and the setting it is asked in. Conditions sit above the answer, here and in Anki: a constraint you only see after answering is a verdict, not a condition.
back
The shortest complete answer.
used for
One line, usually absent: where this result actually turns up. Distinct from prose — prose says what it means, this says where it appears.
proof · prose
A short derivation when it is load-bearing; one sentence of intuition when it earns its place.
verify
Python that checks the identity numerically. Never reaches Anki — it is a check on whoever wrote the card, and it is how three errors in the source were caught.
